Day 01

Linux Fundamentals

Every server runs Linux. Master the file system, permissions, and process management before touching any automation tool.

1
File System Navigation
⌄

Learn to move through the Linux file system. Understanding paths, listing contents, and finding files are skills you'll use every day.

bash
# Print current directory
pwd

# List all files including hidden, with details
ls -la

# Navigate and create directories
mkdir -p ~/projects/devops/day1
cd ~/projects/devops/day1

# Find files by name recursively
find / -name "*.conf" 2>/dev/null

# Disk usage
df -h && du -sh *
💡Use Tab for auto-completion and Ctrl+R to search command history.
2
File Permissions & Ownership
⌄

Understand rwx permission bits, octal notation, and how chmod/chown protect your infrastructure.

bash
ls -l /etc/passwd
chmod 755 script.sh      # rwxr-xr-x
chmod 600 ~/.ssh/id_rsa   # rw------- (private key!)
chown ubuntu:ubuntu /var/www/html
chmod +x deploy.sh && ./deploy.sh
⚠️Never use chmod 777 in production — it grants full access to every user.
3
Process Management
⌄

Monitor and control running processes. Know how to identify resource hogs and terminate them gracefully.

bash
ps aux | grep nginx
htop                  # interactive process viewer
kill -9 1234          # kill by PID
pkill nginx           # kill by name
sleep 60 &            # run in background
jobs && fg %1         # list jobs, bring to foreground

Day 02

Shell Scripting

Stop running commands manually. Write scripts that automate repetitive tasks, handle errors gracefully, and run on a schedule.

1
Variables, Conditionals & Loops
⌄

The building blocks of every shell script. Master these and you can automate almost anything on a Linux system.

bash
#!/bin/bash
NAME="DevOps"
COUNT=5

if [ -f /etc/nginx/nginx.conf ]; then
  echo "Nginx is installed"
else
  echo "Nginx not found"
fi

for i in $(seq 1 $COUNT); do
  echo "Iteration $i of $COUNT"
done
2
Functions & Error Handling
⌄

Production scripts must handle failures gracefully. Use set -e, exit codes, and trap signals for robust automation.

bash
#!/bin/bash
set -euo pipefail

log() { echo "[$(date +%T)] $*"; }

deploy() {
  log "Starting deploy…"
  docker pull myapp:latest || { log "Pull failed"; exit 1; }
  docker compose up -d
  log "Deploy complete ✓"
}

trap 'log "Script interrupted"' INT TERM
deploy
3
Cron Jobs & Scheduling
⌄

Schedule scripts to run automatically using cron. Every DevOps engineer needs to read and write crontab expressions.

bash
crontab -e
# min hour day month weekday command
30 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2&1
*/5 * * * * /opt/scripts/health-check.sh
crontab -l
ℹ️Use crontab.guru to visually build and test cron expressions.

Day 03

Git & Version Control

Git is the foundation of all modern software delivery. Every config file, script, and IaC template you write should live in Git.

1
Core Git Workflow
⌄

The daily loop: stage, commit, push. Understanding the working tree, staging area, and history is essential.

bash
git init && git remote add origin https://github.com/user/repo.git
git status
git add -A
git commit -m "feat: add nginx config"
git push origin main
git log --oneline --graph
2
Branching & Merging
⌄

Feature branches isolate work. Merge or rebase to integrate. Resolve conflicts without fear.

bash
git checkout -b feature/add-monitoring
git add -A && git commit -m "add prometheus config"
git checkout main
git merge --no-ff feature/add-monitoring
git branch -d feature/add-monitoring
3
.gitignore & Secrets
⌄

Never commit secrets to Git. Use .gitignore and environment variables. If a secret is committed, rotate it immediately.

text
# .gitignore
.env
*.pem
*.key
node_modules/
.terraform/
__pycache__/
⚠️GitHub scans all public commits for secrets. Treat a committed secret as compromised — rotate it immediately.

Day 04

Docker Fundamentals

Containers are the lingua franca of modern infrastructure. By end of day, you'll be building, running, and publishing your own images.

1
Install Docker & Core Commands
⌄

Install Docker Engine and learn the commands you'll run dozens of times a day: pull, run, exec, logs, ps, rm.

bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
docker run -d -p 80:80 --name web nginx
docker logs -f web
docker exec -it web sh
docker stop web && docker rm web
2
Write a Production Dockerfile
⌄

Use multi-stage builds to create small, secure images. Always run as a non-root user in production.

dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/node_modules ./node_modules
COPY . .
RUN addgroup -S app && adduser -S app -G app
USER app
EXPOSE 3000
CMD ["node", "server.js"]
3
Push to Docker Hub
⌄

Tag images with semantic versions and push to a registry so your CI/CD pipeline can pull them anywhere.

bash
docker login
docker build -t yourusername/myapp:1.0.0 .
docker tag yourusername/myapp:1.0.0 yourusername/myapp:latest
docker push yourusername/myapp --all-tags

Day 05

Docker Compose

Real applications have multiple services. Docker Compose lets you define, run, and connect them all with one file.

1
Write a docker-compose.yml
⌄

Define a full stack: Node.js + PostgreSQL + Redis. Compose handles networking between services automatically.

yaml
version: '3.9'
services:
  app:
    build: .
    ports: ["3000:3000"]
    environment:
      DATABASE_URL: postgres://user:pass@db:5432/mydb
    depends_on: [db, cache]
  db:
    image: postgres:16-alpine
    volumes: [pgdata:/var/lib/postgresql/data]
  cache:
    image: redis:7-alpine
volumes:
  pgdata:
2
Compose Commands
⌄

The complete Compose CLI you'll use daily — start, stop, rebuild, scale, and debug your stack.

bash
docker compose up -d
docker compose logs -f app
docker compose ps
docker compose exec app sh
docker compose down -v
docker compose build --no-cache
3
Environment Files & Overrides
⌄

Use .env files for secrets and compose overrides to maintain separate dev vs production configs.

bash
# .env (never commit!)
POSTGRES_PASSWORD=supersecret

# docker-compose.override.yml
services:
  app:
    volumes: [./src:/app/src]
    command: npm run dev

Day 06

GitHub Actions — CI/CD

Automate your entire build-test-deploy cycle. By end of day you'll have a working pipeline that fires on every git push.

1
Your First Workflow
⌄

Workflows live in .github/workflows/. Create a YAML file that installs, tests, and builds your project on every push.

yaml
name: CI Pipeline
on:
  push: { branches: [main] }
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci && npm test && npm run build
2
Build & Push Docker Image
⌄

Extend the pipeline to build a Docker image and push it to Docker Hub, tagged with the git commit SHA.

yaml
  docker:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with:
          push: true
          tags: myuser/myapp:${{ github.sha }}
3
Secrets & Environment Variables
⌄

Store credentials safely in GitHub Secrets. Use environment-scoped secrets for staging vs production.

yaml
env:
  API_URL: ${{ vars.API_URL }}
  DB_PASSWORD: ${{ secrets.DB_PASS }}
💡Use vars.* for non-secret config and secrets.* for credentials. Both are masked in logs.

Day 07

Deployment Strategies

How you deploy matters as much as what you deploy. Learn rolling updates, blue-green, and rollbacks to ship with zero downtime.

1
SSH Deploy via GitHub Actions
⌄

Deploy to a remote server over SSH directly from your CI pipeline. Store the private key as a GitHub Secret.

yaml
      - uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ubuntu
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /opt/myapp
            docker pull myuser/myapp:latest
            docker compose up -d --no-deps app
            docker image prune -f
2
Blue-Green Deployments
⌄

Run two identical environments. Deploy to the idle one, test it, then switch traffic. Zero downtime guaranteed.

bash
ACTIVE=$(docker inspect --format '{{.Name}}' live | grep -o 'blue\|green')
NEXT=$([[ $ACTIVE == "blue" ]] && echo "green" || echo "blue")
docker run -d --name app-$NEXT myapp:latest
sed -i "s/$ACTIVE/$NEXT/" /etc/nginx/conf.d/upstream.conf
nginx -s reload
docker stop app-$ACTIVE && docker rm app-$ACTIVE
3
Rollbacks
⌄

Always have a rollback plan. Pin image tags in production and keep previous versions available to redeploy instantly.

bash
docker pull myuser/myapp:abc1234
docker compose up -d --no-deps app
ℹ️Never use only :latest in production — always also tag with a version or git SHA.

Day 08

AWS Essentials

AWS powers a third of the internet. Get hands-on with EC2, S3, IAM, and VPC — the core services every DevOps engineer must know.

1
AWS CLI & IAM Setup
⌄

Never use your root account. Create an IAM user with least-privilege permissions, configure the CLI, and use roles for services.

bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
unzip awscliv2.zip && sudo ./aws/install
aws configure
aws sts get-caller-identity
⚠️Never store AWS credentials in code or Docker images. Use IAM roles for EC2/Lambda instead.
2
EC2 & S3 Essentials
⌄

Launch a server with EC2 and store files or static assets in S3. These are the two most used AWS services in any infrastructure.

bash
aws ec2 run-instances \
  --image-id ami-0c55b159cbfafe1f0 \
  --instance-type t3.micro \
  --key-name my-key
aws s3 mb s3://my-devops-bucket
aws s3 sync ./dist/ s3://my-devops-bucket/ --delete
3
VPC & Security Groups
⌄

Never launch into the default VPC in production. Design a VPC with public and private subnets to control traffic flow.

bash
aws ec2 create-vpc --cidr-block 10.0.0.0/16
aws ec2 create-subnet \
  --vpc-id vpc-xxx \
  --cidr-block 10.0.1.0/24
aws ec2 authorize-security-group-ingress \
  --group-id sg-xxx --protocol tcp --port 80 --cidr 0.0.0.0/0

Day 09

Terraform — Infrastructure as Code

Stop clicking in the AWS console. Define your entire infrastructure in code, version it in Git, and deploy reproducible environments in minutes.

1
Terraform Basics
⌄

Install Terraform, write your first HCL configuration, and deploy a real EC2 instance to AWS.

hcl
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}
provider "aws" { region = "us-east-1" }
resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"
}
bash
terraform init && terraform plan && terraform apply
2
Variables & Outputs
⌄

Parameterize your infrastructure with variables. Export useful values like public IPs as outputs to share between modules.

hcl
variable "instance_type" { default = "t3.micro" }

output "public_ip" {
  value = aws_instance.web.public_ip
}

# override at apply time
terraform apply -var="instance_type=t3.small"
3
Remote State & Workspaces
⌄

Store state in S3 with DynamoDB locking so teams can collaborate without overwriting each other's changes.

hcl
terraform {
  backend "s3" {
    bucket         = "my-tf-state"
    key            = "prod/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "tf-state-lock"
    encrypt        = true
  }
}
terraform workspace new staging
terraform workspace select production

Day 10

Kubernetes Introduction

Kubernetes orchestrates containers at scale. Deploy a real app to a cluster, scale it, and expose it to the internet.

1
Core Concepts & kubectl
⌄

Understand Pods, Deployments, Services, and Namespaces. Install kubectl and connect to a local cluster with minikube.

bash
minikube start
kubectl get nodes
kubectl get pods -A
kubectl run nginx --image=nginx --port=80
kubectl describe pod nginx
kubectl logs nginx
kubectl delete pod nginx
2
Deployment & Service YAML
⌄

Deploy your Docker image with a Deployment (manages replicas) and expose it with a Service (manages networking).

yaml
apiVersion: apps/v1
kind: Deployment
metadata: { name: myapp }
spec:
  replicas: 3
  selector: { matchLabels: { app: myapp } }
  template:
    metadata: { labels: { app: myapp } }
    spec:
      containers:
        - name: myapp
          image: yourusername/myapp:1.0.0
          ports: [{ containerPort: 3000 }]
---
apiVersion: v1
kind: Service
metadata: { name: myapp-svc }
spec:
  selector: { app: myapp }
  ports: [{ port: 80, targetPort: 3000 }]
  type: LoadBalancer
bash
kubectl apply -f deployment.yaml
kubectl get pods -w
kubectl scale deployment myapp --replicas=5
3
ConfigMaps, Secrets & Health Probes
⌄

Inject configuration and secrets into pods. Add liveness and readiness probes so Kubernetes can self-heal your application.

yaml
spec:
  containers:
    - name: myapp
      envFrom:
        - configMapRef: { name: app-config }
        - secretRef: { name: app-secrets }
      livenessProbe:
        httpGet: { path: /healthz, port: 3000 }
        initialDelaySeconds: 10
      readinessProbe:
        httpGet: { path: /ready, port: 3000 }
        initialDelaySeconds: 5
💡Liveness restarts a broken container. Readiness removes it from the load balancer until it's ready.
